# Внутренний почтовый сервер: варианты, требования, миграция

Решение о направлении принято 17.11.2026: **почта переезжает в свою сеть (on-premises)**, внешний сервис mail.nic.ru выводится из эксплуатации. Документ дополняет карточки **PB-48** (почта) и **PB-47** (разделение серверных ролей).

## Что должно закрыть решение

| № | Требование | Зачем |
|---|---|---|
| 1 | Глобальная адресная книга, собираемая из Active Directory | Единый список сотрудников вместо ручного сбора адресов |
| 2 | Общие календари, встречи, бронирование переговорных | Сейчас живут в личных файлах и на отдельных людях |
| 3 | Управляемые списки рассылки по отделам | Рассылки перестают быть «списком в блокноте» |
| 4 | Аутентификация через AD (SSO или синхронизация паролей) | Один пароль, один процесс увольнения |
| 5 | SMTP-релей для системных уведомлений (1С, бэкапы, мониторинг) с ограничением по IP | Сейчас часть писем блокируется как спам |
| 6 | Антиспам и антивирус на входе | Собственная фильтрация вместо «как настроит провайдер» |
| 7 | Архив переписки и журналирование с настраиваемым сроком хранения | Восстановление переписки при увольнении и претензиях |
| 8 | Веб-клиент, Outlook и мобильные устройства | Привычные сотрудникам сценарии должны сохраниться |
| 9 | Квоты, отчёты, резервное копирование ящиков | Эксплуатация и восстановление |
| 10 | TLS на всех протоколах, DKIM, SPF, DMARC | Доставка письма без попадания в спам у контрагентов |

## Кандидаты для своей сети

| Продукт | Платформа | AD и GAL | Календари и переговорные | Антиспам | Сложность | Комментарий |
|---|---|---|---|---|---|---|
| **Kerio Connect** | Windows / Linux / macOS | Да, синхронизация пользователей и GAL | Да | Встроенный | Низкая | Практичный вариант для Windows-инфраструктуры: понятная консоль, AD-интеграция, Outlook-коннектор, есть встроенный антиспам и архив |
| **MDaemon** | Windows | Да, AD-интеграция и GAL | Да | Встроенный + антивирус | Низкая | Классика для небольших компаний, сильные правила фильтрации, работает на Windows Server |
| **Zimbra** | Linux | Да, LDAP/AD-синхронизация | Да | Встроенный + отдельный шлюз | Средняя | Функционально близок к Exchange, но требует Linux-компетенции и отдельного администрирования |
| **Mailcow / Postfix+Dovecot** | Linux, Docker | Частично (LDAP-аутентификация, GAL — через доп. компоненты) | Ограниченно (CalDAV) | Через Rspamd | Высокая | Гибко и бесплатно, но это сборка «своими руками» без вендорской поддержки |
| **Exchange Server 2019** | Windows Server 2019/2022 | Полная | Полная | Встроенный | Высокая | Максимальная совместимость с Outlook и привычная админка, но требует новых серверов, отдельных лицензий и квалификации; на 2012 R2 не устанавливается |

**Рекомендация для вашего профиля** (Windows-инфраструктура, около 300 учётных записей, один администратор, потребность в GAL и календарях): **Kerio Connect или MDaemon** на отдельной виртуальной машине с поддерживаемой ОС. Exchange оправдан только при жёстком требовании полного Exchange-функционала и готовности содержать новые серверы и лицензии. Zimbra и Mailcow — если появится Linux-компетенция.

Точные матрицы поддерживаемых ОС, версий Outlook и мобильных клиентов на дату выбора нужно запросить у вендора: продукты обновляются, а сервер 2012 R2 вне поддержки, поэтому почтовый сервер ставится только на Windows Server 2022/2025 или поддерживаемый Linux.

## Требования к площадке

- **Отдельная виртуальная машина**, не на контроллере домена (PB-47), в серверном сегменте, отдельно от файловых ресурсов.
- ОС — поддерживаемая (2022/2025), с регулярным патчингом; не 2012 R2.
- Ресурсы для 150–300 ящиков: 4 vCPU, 8–16 ГБ памяти, 300–500 ГБ диска под ящики и архив (с запасом на рост), отдельный том под журналы и архив.
- Публикация только нужных портов: 25 (MX), 587/465 (отправка), 993/143 (IMAP), 443 (веб-клиент). Остальное закрыто.
- Статический внешний IP и обратная запись PTR — обязательны, иначе письма уходят в спам.
- SMTP-поток: интернет → MX (антиспам-шлюз) → почтовый сервер → клиенты. Исходящие — через тот же шлюз, чтобы не попасть в чёрные списки.
- Резервное копирование: снапшот ВМ плюс экспорт ящиков и настроек; проверить восстановление отдельного ящика, а не только сервера.

## Чек-лист миграции

1. Инвентаризация: ящики, алиасы, списки рассылки, квоты, общие ящики, настройки мобильных клиентов на mail.nic.ru.
2. Чистка Active Directory: без этого глобальная адресная книга покажет `admin999`, `test` и записи с битыми именами (PB-41).
3. Согласование окна и порядка: миграция волнами по отделам, а не «всё сразу».
4. Заранее снизить TTL MX- и SPF-записей до 300 секунд (минимум за сутки до переключения).
5. Подготовить DNS: MX, SPF, DKIM (сгенерировать ключ и опубликовать), DMARC в режиме `p=none`, autodiscover.
6. Развернуть сервер, настроить аутентификацию через AD, списки рассылки и общие папки; проверить GAL.
7. Тестовый ящик: приём и отправка наружу, проверка SPF/DKIM по заголовкам, проверка мобильного клиента.
8. Пилотная группа 5–10 человек: реальная работа неделю, сбор замечаний.
9. Миграция ящиков по IMAP (IMAPSync или встроенный инструмент вендора), включая папки и флаги.
10. Переключение MX на новый сервер; отправка — через шлюз с PTR и SPF.
11. Проверка доставки в обе стороны: с внешних адресов (Gmail, Яндекс, корпоративные домены контрагентов), из 1С и мониторинга.
12. Перенастройка клиентов: Outlook (новый профиль), мобильные устройства, веб-клиент; инструкция сотрудникам.
13. Работа в параллель 2–4 недели (внешний сервис принимает почту на старый адрес или настроен форвардинг), затем отключение старого сервиса и возврат TTL.
14. Регламент: кто создаёт и удаляет ящики, срок хранения архива, правила пересылки при увольнении, ротация паролей.

## Риски и как их снимать

| Риск | Как снижать |
|---|---|
| Письма теряются при переключении MX | Снизить TTL заранее, держать старый сервис включённым, мигрировать ящики до переключения, а не после |
| Письма попадают в спам у контрагентов | PTR, SPF, DKIM, DMARC, отдельный IP с нормальной репутацией; проверка через mail-tester до боевого включения |
| Простой почты в рабочий день | Переключение вечером или в выходной, инструкции заранее, дежурство администратора |
| Клиенты не подключаются после переключения | Заранее подготовить профили Outlook и инструкции, пилотная группа проверяет мобильные устройства |
| Нагрузка на одного администратора | Выбирать продукт с вендорской поддержкой и понятной консолью, а не сборку из компонентов |
| Нет резервной копии ящиков | Настроить экспорт ящиков и снапшоты, проверить восстановление отдельного ящика до миграции |
| Антиспам пропускает или режет лишнее | Логировать и разбирать первые две недели, настроить карантин вместо удаления |

## Критерии приёмки

- Глобальная адресная книга соответствует Active Directory (после чистки каталога).
- Общие календари и бронирование переговорных работают, сотрудники ими пользуются.
- Уведомления из 1С и мониторинга доходят через релей, отправитель не попадает в спам.
- Внешняя доставка проверена с 5+ внешних доменов, оценки SPF/DKIM/DMARC — pass.
- Восстановление отдельного ящика из резервной копии выполнено и зафиксировано.
- Архив переписки включён, срок хранения утверждён.
- Старый сервис отключён, TTL вернулся к нормальному значению, документы обновлены.
