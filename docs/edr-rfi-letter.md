# Письмо вендорам: запрос предложений по EDR

Шаблон для запроса коммерческих предложений. Опирается на `docs/edr-selection.md` (критерии, стоп-условия, матрица оценки). Отправлять одновременно 3–4 поставщикам, чтобы получить сравнимые ответы.

Перед отправкой заполнить: дату, ФИО и контакты, срок ответа, примерное число серверов и рабочих станций. Не раскрывать лишнего: вендору достаточно знать платформы, количество объектов и требования.

---

## Тема

Запрос предложения: EDR для инфраструктуры с контроллером домена на Windows Server 2012 R2 и планом миграции

## Текст

Уважаемые коллеги!

Мы рассматриваем внедрение решения класса EDR для защиты серверов и рабочих станций. Просим предоставить коммерческое предложение и технические ответы по пунктам ниже.

**Исходные данные**

- Домен Active Directory, один контроллер домена на **Windows Server 2012 R2** (вывод из эксплуатации и переход на поддерживаемую ОС запланирован; в переходный период нужен план защиты).
- Рабочие станции: Windows 10/11, часть машин на устаревших сборках, есть Windows 7/8 — просим отдельно указать, поддерживаются ли они.
- Серверы: файловый сервер, SQL Server 2016 с базами 1С, терминальные сессии. Лицензирование 1С защищено USB-ключами HASP/Sentinel.
- Уже используется антивирус Kaspersky Endpoint Security на рабочих станциях; управления через Kaspersky Security Center пока нет.
- Своего центра мониторинга безопасности нет: вопрос разбора срабатываний для нас критичен.

**Что просим предоставить**

1. Матрицу поддерживаемых ОС с датами окончания поддержки: Windows Server 2022/2025, Windows 10/11, а также позицию по Windows Server 2012 R2 и Windows 7/8.
2. Перечень функций, которые **не работают** на Windows Server 2012 R2 и станут доступны только после миграции (например, проверка скриптов через AMSI, поведенческие правила, защита учётных данных).
3. Рекомендованные вами исключения для контроллера домена: база AD, SYSVOL, журналы, базы 1С, компоненты HASP — с обоснованием каждого исключения.
4. Архитектуру управления: облачная консоль или локальная, какие компоненты требуются, как выполняется обновление компонентов и баз в закрытом сегменте (свой репозиторий, прокси, ретранслятор).
5. Требования к ресурсам агента на контроллере домена и файловом сервере: процессор, память, диск, влияние на задержки аутентификации — с замерами, а не «по паспорту».
6. Возможности обнаружения по модели MITRE ATT&CK: какие техники покрываются, есть ли готовые отчёты и демонстрация детектов на краже учётных данных, Kerberoasting, боковом перемещении.
7. Функции реагирования: изоляция хоста, карантин, удаление артефактов, откат изменений — с ограничениями по ОС.
8. Интеграция: API, выгрузка событий в SIEM или лог-сервер (syslog/CEF/webhook), экспорт отчётов для аудита ИБ и страхования.
9. Управляемое обнаружение и реагирование (MDR): оказывается ли, кем, с каким SLA на разбор срабатывания, как передаются инциденты, что входит в стоимость.
10. Лицензирование: по серверам, ядрам или пользователям; отдельно ли считаются терминальные серверы; как учитываются виртуальные машины; минимальный объём закупки.
11. Условия пилота: срок, объём (серверы и рабочие станции), кто выполняет развёртывание, какие критерии считаются успехом, стоимость пилота и зачёт его в проект.
12. Требования к ОС после миграции: версии, необходимые патчи и компоненты, ограничения по политикам безопасности.
13. Референсы: 2–3 внедрения сопоставимого масштаба, желательно с 1С и терминальными серверами; возможность короткого разговора с клиентом.
14. Сроки поставки, внедрения и техподдержки: SLA на реакцию, порядок эскалации, наличие документации на русском языке.

## Что приложить к письму

- Матрицу оценки с весами из `docs/edr-selection.md` — чтобы вендор понимал, по каким критериям его будут сравнивать, и не присылал общие презентации.
- Требование отвечать по пунктам и нумерацией — иначе сравнение превращается в чтение маркетинговых материалов.

## Как читать ответы

| Признак в ответе | Что это значит |
|---|---|
| «Поддерживается 2012 R2, но часть функций недоступна» | Ожидаемо. Не считать решением для текущего DC, только переходной мерой |
| Нет ответа про исключения для AD | Вендор не работал с контроллерами домена: будет больно при внедрении |
| Нет ответа про закрытый сегмент и обновления | В закрытой сети агент окажется без баз |
| MDR «включён в лицензию» без SLA и описания процесса | Разбор срабатываний останется на вас |
| Отказ от пилота | Повышенный риск: EDR на DC без пилота — это остановка аутентификации |
| Матрица ATT&CK без демонстрации | Красивая табличка, реального покрытия не видно |
